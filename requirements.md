# WanderlustAI — Project Requirements

## 1. Project Overview

**WanderlustAI** is an AI-powered personalized travel planning web application. Users answer a short questionnaire about their travel style, interests, budget, and preferences. The system processes these inputs and returns tailored destination recommendations, activity suggestions, and an optional sample itinerary — all generated by a large language model.

The project is built as a full-stack portfolio piece demonstrating real-world skills in backend API design, AI integration, and modern frontend development. It is publicly deployed and open-source.

---

## 2. Goals

- Deliver a seamless, end-to-end travel planning experience driven by user preferences
- Demonstrate production-quality Django REST Framework API design with clean separation of concerns
- Showcase prompt engineering — structuring user inputs into intelligent, context-aware LLM prompts
- Ship a live, deployed application accessible via a public URL
- Serve as a primary portfolio artifact during active job applications targeting backend and full-stack Python roles

---

## 3. Scope

### 3.1 In Scope

- Interactive multi-step questionnaire (travel style, interests, duration, budget, climate, location)
- Django backend with a secure `/api/trip-planner/` endpoint
- OpenAI API integration (GPT-4o) with structured prompt construction
- AI-generated response parsed into structured JSON (destinations, activities, sample itinerary)
- React frontend rendering results as responsive destination cards
- Deployment on DigitalOcean via NGINX + Gunicorn
- Public GitHub repository with a well-documented README

### 3.2 Out of Scope (v1)

- User authentication, profiles, or saved trips
- Multi-provider LLM fallback (Claude, Gemini)
- Payment or subscription features
- Native mobile application

## 4. Functional Requirements

### 4.1 Questionnaire Flow (Frontend)

| ID | Requirement |
|----|-------------|
| F-01 | The UI presents questions one step at a time in a clean, mobile-friendly layout |
| F-02 | Travel Style selection: Luxury, Budget, Adventure, Cultural, Relaxation |
| F-03 | Interests selection (multi-select): Food, Hiking, Nightlife, History, Shopping, Beaches, Nature |
| F-04 | Trip Duration input: number of days |
| F-05 | Budget Range input: low / medium / high or numeric range |
| F-06 | Preferred Climate: Tropical, Temperate, Cold, Arid, Any |
| F-07 | Current Location or Departure Region: free text or dropdown |
| F-08 | A loading state is displayed while waiting for the AI response |
| F-09 | Results render as destination cards with name, match reason, top attractions, and activities |
| F-10 | An optional sample itinerary preview is displayed beneath the destination cards |

### 4.2 Backend API

| ID | Requirement |
|----|-------------|
| B-01 | `POST /api/trip-planner/` accepts a JSON payload of user preferences |
| B-02 | The endpoint validates all incoming fields before processing |
| B-03 | A prompt builder module constructs a structured, context-rich prompt from user data |
| B-04 | The backend calls the OpenAI API and handles errors gracefully (timeouts, quota limits, rate limits) |
| B-05 | The raw LLM response is parsed and returned as a clean, structured JSON object |
| B-06 | API responses follow a consistent schema regardless of LLM output variation |
| B-07 | Sensitive configuration (API keys, secrets) is managed via environment variables |

### 4.3 AI Recommendation Engine

| ID | Requirement |
|----|-------------|
| A-01 | The prompt instructs the model to return 3–5 destination suggestions |
| A-02 | Each destination includes: name, country, match rationale, top 3 attractions, recommended activities |
| A-03 | The model is instructed to return valid JSON only — no freeform prose in the response body |
| A-04 | A sample day-by-day itinerary (3–5 days) is included for the top recommended destination |
| A-05 | Prompt is versioned in the codebase to allow iterative improvement |

## 6. System Architecture

```
User (Browser)
    │
    ▼
React Frontend
    │  POST /api/trip-planner/  (JSON: user preferences)
    ▼
Django REST Framework
    ├── Input validation (DRF Serializers)
    ├── Prompt Builder (structures preferences → LLM prompt)
    └── OpenAI API Client
            │
            ▼
        OpenAI API (gpt-4o)
            │  Structured JSON response
            ▼
    Response Parser
            │
            ▼
React Results View (destination cards + itinerary)
```

**Deployment Stack:** DigitalOcean Droplet → NGINX (reverse proxy) → Gunicorn → Django

## 7. API Contract

### Request — `POST /api/trip-planner/`

```json
{
  "travel_style": "adventure",
  "interests": ["hiking", "nature", "food"],
  "duration_days": 10,
  "budget": "medium",
  "preferred_climate": "tropical",
  "departure_location": "Dhaka, Bangladesh"
}
```

### Response

```json
{
  "destinations": [
    {
      "name": "Chiang Mai",
      "country": "Thailand",
      "match_reason": "...",
      "top_attractions": ["Doi Inthanon", "Elephant Sanctuary", "Night Bazaar"],
      "activities": ["jungle trekking", "cooking class", "temple hopping"]
    }
  ],
  "sample_itinerary": {
    "destination": "Chiang Mai",
    "days": [
      { "day": 1, "plan": "Arrive, check in, explore the Old City..." },
      { "day": 2, "plan": "Day trek to Doi Inthanon National Park..." }
    ]
  }
}
```

## 8. Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| LLM returns malformed JSON | Medium | High | Enforce JSON-only output in system prompt; add a fallback parser with error response |
| OpenAI API latency exceeds 15s | Low | Medium | Set explicit timeout; show progressive loading UI |
| API key exposed in repo | Low | Critical | Use `.env` + `.gitignore`; audit commits before push |
| LLM output quality is inconsistent | Medium | Medium | Version and iterate on prompt; test with diverse inputs |
